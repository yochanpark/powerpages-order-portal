# Power Pages 주문 접수 포털

Microsoft **Power Pages**로 만든 외부 사용자용 주문 접수 포털이다.
거래처가 포털에서 주문을 등록하면 Dataverse에 행이 쌓이고,
Power Automate 흐름이 주문번호 채번과 담당자 통보를 맡는다.

설계부터 개발·배포·운영 이관, 운영 중 장애 대응과 변경 요청까지 **전 과정을 혼자 맡았다.**
고객사 납품 건이라 산출물(managed solution, 이미지, 실데이터)은 올리지 않고,
**무엇을 어떻게 만들고 운영했는지만 기록한 문서**다.

| 한눈에 | |
|---|---|
| 기간 · 역할 | 2026.08 ~ 운영 중 · 단독 수행(설계 · 개발 · 배포 · 운영 이관 · 유지보수) |
| 설계 | 주문번호 **채번 규칙을 흐름 밖 설정 테이블로 분리**(유형이 늘어도 흐름 수정 없음), 통보는 "생성"이 아니라 **"주문번호 열 변경"** 에 트리거, 운영 403 이후 조회 경로를 **Web API → Liquid 서버 렌더링**으로 전환 |
| 코드 작성 | 로그인 화면 CSS 재정의, Liquid `fetchxml` 조회, 기본 제공 프로필 페이지에 Footer 스크립트로 기능 추가, 주문서 저장·거래처 검증 JS, 흐름 식 |
| 기능 | 구성요소 267개 포털 — 주문서 입력·목록·상세·인쇄, 프로필(주소 검색·전화 자동 대시·거래처 검색/등록), 채번·통보 흐름 |
| 인프라 | managed 솔루션 1.0.0.1 → 1.0.0.4, 지역 불일치로 **운영 환경을 새로 구성해 이관**, CSP·Web API 필드·보안 헤더 사이트 설정 |
| 유지보수 | 운영 전용 Web API 403 추적·우회, CSP로 멈춘 사이트 복구, Site Checker 항목별 조치·수용 판단, 잘못된 거래처 데이터 원인 분석과 입력 검증 |
| 기술 | Power Pages · Dataverse · Power Automate · Liquid · JavaScript · CSS · 솔루션 패키징 |

## 기록 원칙

솔루션 패키지·흐름 정의와 직접 작성한 페이지 코드, 운영 중 남긴 작업 기록(오류 메시지 원문, 콘솔 출력)을 근거로 했다.
원인을 끝내 특정하지 못한 것은 그렇다고 적었고, 시도했다가 되돌린 것도 남겼다.
플랫폼 기본값이 섞여 있는 부분은 기본값이라고 밝혔다.

| 자리표시자 | 원래 값의 성격 |
|---|---|
| `{PREFIX}_` / `{PREFIX2}_` | Dataverse 게시자 접두어 2종 |
