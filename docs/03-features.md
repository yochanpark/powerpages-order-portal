# 3. 기능

포털과 흐름이 사용자에게 제공하는 기능이다. 구현 코드는 [2. 코드 작성](02-code.md)에 있다.

## 포털 구성

Power Pages 사이트는 Dataverse 테이블에 저장되는 구성요소의 묶음이다.
이 사이트는 **267개** 구성요소, **20종** 타입으로 이루어져 있다.

| 영역 | 내용 |
|---|---|
| 테마 | `bootstrap.min.css`(그리드·컴포넌트) + `portalbasictheme.css`(기본 테마) 위에 사이트 전용 `theme.css`로 재정의 |
| 웹파일 | 로고(상단 메뉴용·64px)와 로그인/인쇄 화면용 이미지 20여 종, `PWAManifest.json`, `robots.txt` |
| 로그인 | 로컬 계정 전용 카드형 화면. 외부 인증 버튼·불필요한 요소 숨김 |

## 주문

| 화면 | 기능 |
|---|---|
| 주문서 입력 | 기본 정보(발주유형·사이즈·제본방식·부수), 표지 5개 항목, 내지 사양(색지·간지 드롭다운), 배송 정보, 첨부 |
| 배송 정보 | 머리줄 **기본정보 체크** — 켜면 본인 등록 정보로 채우고, 끄면 비워서 직접 입력. 기존 주문을 열 때는 꺼진 채 시작해 저장된 배송지를 덮어쓰지 않는다 |
| 거래처 기본값 | 새 주문이면 프로필 회사명을 넣고, 같은 이름의 거래처 레코드가 있으면 조회 열까지 연결. 없으면 등록 창을 프로필 정보로 미리 채운다 |
| 주문 목록 | 진행 상태 필터, 행을 누르면 상세 |
| 상세 · 인쇄 | 주문 한 건을 보여주고 인쇄용 화면 제공 |

운영 이관 뒤 고객사 요청으로 주문서를 정리했다 —
발주유형 한 항목과 쓰지 않는 입력란 4개 삭제, 표지 항목 5개로 축소,
사이즈·제본방식·부수를 기본 정보로 이동, 내지 사양을 자유 입력에서 드롭다운으로.

## 프로필

| 기능 | 내용 |
|---|---|
| 주소 검색 | 주소 입력란 옆 버튼 → Daum 우편번호 팝업 → 주소·우편번호 자동 입력 |
| 전화번호 자동 대시 | 숫자만 쳐도 `010-1234-5678` 형태로 바뀜, 11자리 제한 |
| 이메일 확인 안내 띠 | 숨김 |
| 저장 후 이동 | 저장하면 로그아웃 → 로그인 화면 → 로그인하면 주문확인 페이지 |
| 회사명 검색·등록 | 회사명 옆 검색 버튼 → 거래처 검색 창, 없으면 별도 등록 창(회사명·성명·전화·핸드폰·이메일) |
| 화면 정리 | 배치는 그대로, 글씨·입력란·버튼 크기와 간격만 키움 |

## 거래처 등록

주문서와 프로필 두 곳의 등록 창에서 새 거래처를 만든다.
회사명에 주문번호 형식·숫자만·한 글자를 넣으면 막는다(2026-10-01 추가).
등록 창의 안내 글씨(placeholder)는 5개 칸 모두 같은 흐린 스타일로 맞췄다.

## 주문번호 채번 흐름

```
트리거: 행 추가/수정/삭제 (Dataverse)
  ↓
OrderType     (Compose)        트리거 행의 주문유형 열을 꺼낸다
  ↓
NumberConfig  (Dataverse)      채번 설정 테이블을 유형명으로 조회
  ↓
조건          (If)             분기
```

## 주문번호 확정 시 담당자 통보 흐름

```
트리거: 행 수정
        대상 테이블 = 주문 테이블
        필터링 특성 = 주문번호 열          ← 이 열이 바뀔 때만 발화
  ↓
거래처 ID 기준으로 행 가져오기  (Dataverse GetItem)
        accounts 테이블, 주문 행의 거래처 조회 열 값으로 조회
  ↓
메일 보내기 (V2)               (Office 365 Outlook)
```

거래처명은 주문 행에 없고 조회 열로만 있어서, 메일을 보내기 전에 `accounts`를 한 번 조회해 이름을 가져온다.
메일에는 주문 No. / 거래처 / 발주유형 세 줄이 담긴다.

## 첨부파일

50MB 이하는 흐름이 SharePoint 주문번호 폴더에 올리고, 넘는 파일은 폴더 링크를 안내한다([1. 설계](01-design.md)).
