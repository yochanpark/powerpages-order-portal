# 1. 설계

외부 거래처가 포털에 로그인해 주문을 등록하면 Dataverse에 행이 쌓이고,
Power Automate 흐름이 주문번호를 매기고 담당자에게 알린다.
이 구조를 어떻게 나눴고, 각 자리에서 무엇을 골랐는지 적는다.

## 전체 구조

```
거래처(외부, 로컬 계정)
  │  로그인 · 주문 등록/조회 · 프로필 · 거래처 등록
  ▼
Power Pages 포털 ──────────────▶ Dataverse
  │                               ├ 주문 테이블 ──┬─▶ 채번 흐름 ── 채번 설정 테이블 조회 → 주문번호 기록
  │                               │               └─▶ 통보 흐름 (주문번호 열 변경 시) → 담당자 메일
  │                               ├ 채번 설정 테이블 (유형별 접두어 · 현재 번호)
  │                               └ 거래처(accounts) · 연락처(contacts)
  │
  └─ 첨부파일 ──▶ 흐름 ──▶ SharePoint 주문번호 폴더
```

## 데이터

| 테이블 | 역할 |
|---|---|
| 주문 | 주문서 한 건 = 한 행. 거래처·연락처를 조회(lookup) 열로 연결 |
| 채번 설정 | 주문 유형별 접두어와 현재 번호. 흐름이 유형명으로 찾아 쓴다 |
| 거래처 · 연락처 | 표준 테이블. 포털 로그인 사용자 = 연락처 |

## 채번 규칙을 흐름 밖으로 뺐다

주문 유형별 채번 설정을 Dataverse 테이블에 두고, 흐름은 유형명으로 그 행을 조회한다.
**유형이 늘어도 흐름을 고치지 않는다. 설정 테이블에 행 하나를 추가하면 된다.**

대가도 있다. 솔루션은 구조만 옮기고 데이터는 옮기지 않으므로,
운영 환경으로 옮길 때 설정 테이블의 **행**도 따로 넣어야 했다([4. 인프라](04-infra.md)).

## 통보는 "생성"이 아니라 "주문번호 열 변경"에 걸었다

통보 흐름의 트리거 필터링 특성을 주문번호 열 하나로 지정했다.
주문이 만들어지는 시점이 아니라 **채번이 끝난 시점**에 메일이 나가고,
다른 열을 고칠 때는 발화하지 않는다. 메일에 주문번호를 실을 수 있는 것도 이 때문이다.

처음(2026-06-26)에는 "행이 추가될 때"에 걸었는데, 채번 흐름이 번호를 쓰기 **전에** 통보 흐름이 먼저 돌아
번호 없는 메일이 나갔다. 두 흐름의 순서를 보장할 수 없으니 **채번 결과(열 변경) 자체를 트리거로** 삼았다.
필터링 특성 칸은 동적 콘텐츠를 받지 않아 열 논리 이름을 직접 적는다.

## 인증과 권한

- **로컬 계정만** 쓴다. 외부 거래처라 조직 계정이 없다.
  로그인 화면에서 Entra ID·외부 공급자 버튼을 가렸다 —
  다만 CSS로 가린 것은 접근 통제가 아니므로, 실제로 막으려면 사이트 설정에서 공급자를 끈다.
- 주문 테이블 권한은 **연락처 범위** — 로그인한 연락처에 연결된 주문만 보인다.
- Web API로 열어 둔 열은 와일드카드(`*`) 대신 **페이지가 실제로 읽고 쓰는 열만** 나열했다([4. 인프라](04-infra.md)).

## 첨부파일

**50MB 이하는 Base64로 흐름에 넘겨 SharePoint 주문번호 폴더에 올리고,
넘는 파일만 폴더 링크를 따로 안내**한다.
외부 고객은 Microsoft 365 계정이 없어 조직 SharePoint에 직접 올릴 수 없으므로
업로드는 흐름이 대신한다. 이 제약 때문에 "전부 링크로 올리기"로 바꾸려던 시도를 되돌렸다([5. 유지보수](05-maintenance.md)).

## 배포는 managed 솔루션

운영 환경에서 고칠 일이 없도록 **managed**로 내보냈다.
구성요소가 잠겨 대상 환경에서 임의 수정이 되지 않고, 솔루션을 제거하면 함께 정리된다.

## 데이터 읽기 경로를 바꿨다 — Web API → Liquid

처음에는 페이지 JS가 Power Pages Web API로 주문을 읽었다.
운영 환경에서만 Web API 조회가 403으로 거부돼([5. 유지보수](05-maintenance.md)),
**페이지가 서버에서 렌더링될 때 Liquid `fetchxml`로 읽어 숨은 요소에 심고 JS는 그것만 읽는 구조**로 바꿨다.
상세·인쇄·목록 필터를 모두 이 경로로 옮겼고, 저장은 계속 Web API로 한다.
코드는 [2. 코드 작성](02-code.md)에 있다.
